# 原典のルール

原典の保存・作り直した版への差し替え・原典の修正・話者の付け方の決まり。`CLAUDE.md` から分けた（中身はそのまま）。原典を扱う作業の前に、必ず全文を読む。

- 「原典の修正記録」「作り直した版への差し替え」の記録は、`notes/source-edits.md`（入口）から分けた、話数100ずつのファイル（`notes/source-edits/000-099.md` など）の、その話の範囲のファイルに書く。以下で「`notes/source-edits.md` に書く」とあるのは、このファイルのこと（2026-10-09に分けた）。
- 原典は `source/NNN_タイトル.txt`（連番、時系列順）に追加する。後から書き換えない（上の小さな直しは除く）。時系列で前に入る話は、既存の番号を変えず空いている番号（000など）を使う。
- 話数に端数がついた話（365.1など）は、ファイル名の番号の後ろに英小文字を付けて `source/365a_第365.1話「タイトル」.txt` のように保存する（2つ目以降は365b、365c…）。こうするとファイル名の並びで365の次に来る。前の話の原典の末尾にも「※次の話は…」の注記を入れておく（ユーザーの指示）。
- 保存したら、アップロード元と `cmp` で一致を確認する。
- 誤字や、主語が抜けているなどの小さな直しは、ユーザーの指示があるときだけ原典に入れてよい。ただし、一目でわかる誤字（「見落とり」→「見劣り」、「孵って」→「帰って」、ポテンシャルの効果文のタイプの書き間違いなど）は、聞かずに直して原典の修正記録に書く。報告で「誤字なのでは」と聞かない（ユーザーより）。1文字だけ紛れ込んだもの（446「“カいつもの皆”」、450「指令：;全開指令」、453「そのｌ器用な」「メイドさんにrドナドナ」など）はGPTの変換で入った誤字なので、同じく聞かずに消す（ユーザーより）。何をどう見ても作者の書き間違いのもの（System表示で場にいないポケモンの名前が出ている、名前の取り違えなど。078の『高貴なる装甲戦車』の「ディバイソンの守りの力が強化された」）も、原文どおり残さずに聞かずに直す（ユーザーより）。迷う程度のものは直さずに報告する。直したら `notes/source-edits.md` の「原典の修正記録」に、話数・元の文・直した文を書く。原典の修正は、保存や設定資料の反映とは別のコミットにする。
- 原典の保存と設定資料の反映は、別々のコミットにする。
- 作り直した版（GPTの変換版）が届いたら、話数にかかわらず差し替える（ユーザーの指示。第100話から先と004〜099は差し替え済みで、**000〜003の4話がまだ**（2026-10-10時点）。000〜099も届いたものから順に差し替える。届いたら聞かずに差し替えてよい）。000〜099は旧版で話者の付け方や地の文が今と違うので、差し替えたら、旧版と新版で話者が変わった台詞（AA内のコメントの持ち主など）と、旧版の地の文にしかなかった説明を洗い出し、設定資料（あらすじ・キャラのファイル・関係図など）でそれを根拠にしている箇所を探して直す。話者が変わった台詞は「作り直した版への差し替え」の行に書く（ユーザーより）。旧版（初期の変換）はダイスを落としていることが多い（004でもストライク度など2つが抜けていた。ユーザーより）ので、新版のダイスを全部数えて `story/dice.md` と突き合わせ、増えたものは表・あらすじ・キャラのファイルに入れる。差し替える前に旧版と台詞・表示を双方向で突き合わせる。新版だからといって完全に正しいとはしない（ユーザーより、2026-10-10）。台詞・表示・ダイス・数字が旧版と食い違うところは、どちらが正しいかを見比べて決め、決めきれないものはユーザーに聞く。新版で旧版の台詞や表示が少し抜けているだけなら、ユーザーに聞かずに旧版から補ってから保存してよい（この場合はアップロード元との `cmp` は一致しないので、補った箇所を `notes/source-edits.md` の「作り直した版への差し替え」に書く）。大きく抜けている、書式が違うなどのときはユーザーに伝える。
- 話者（【名前】）は新版のままにして、手を付けない（ユーザーの指示。手間を減らすため）。ただし、同じ人物が1つの話の中で別の名前（【ジュピター】と【コーネリア】など）で書かれていて不便なときは、その話でいちばん多い名前にそろえてよい（気にしなくていい、とユーザーより。2026-10-10）。そろえたら原典の修正記録に書く。明らかにおかしいと気づいた時だけ一言報告し、直すのはユーザーに言われた時だけ。ただし、話者名の明らかな誤字（【ベルなデッタ】→【ベルナデッタ】など、誰のことか一目でわかる表記の誤り）は、聞かずに直して原典の修正記録に書いてよい（ユーザーより。ルールを硬く当てはめすぎない）。横入りのコメント（AA内）は、AAの都合で先に置かれるが後の台詞にあたる（ユーザーより）。話者を付けたら、【名前（AA内）】のブロック（続けて並ぶものはまとめて）を、それが受けている台詞（基本はすぐ後の台詞のブロック）の後ろへ動かして保存する（ユーザーの指示。100〜301はさかのぼって動かした）。動かさないのは、すぐ後が台詞でない（System・表示・ダイス・図鑑・地の文など）ときと、下の「直前の人物の続き」の例外で、すぐ後の人物がそのコメントに返しているとき。台詞の末尾の「>>名前」は、その人物が話しているか、その存在について話しているかのどちらか。その場にそのキャラがいるなら、確定でそのキャラが話している（ユーザーより）。中身が合わないように見えても、AA内のコメントは直後の1〜2行の台詞を受けた、さらに後の反応として読み直すと「>>」のとおりで合うことが多い（234・236。ユーザーより）。話者のない【AA内】（【AA内補足】）は、基本的にそのすぐ後の台詞の人物のもの（ユーザーより）。「>>名前」があればそちらを優先する。ただし、中身が直前の人物の台詞の続き（直前の台詞を言い足したもの）で、直後の人物の台詞がそれへの返しになっているときは、直前の人物のもの（220・243。243はユーザーの確認済み。249もこの例に挙げていたが、スクショではすぐ後のライザのAAの文字で、ライザの台詞の言い足しだった）。この例外は、中身から「こっちの方が合いそう」と推し量って使わない。迷う程度ならすぐ後の人物にする（279・280・265で例外を当てはめすぎた。ユーザーより）。変換版で【AA内】に分けられていても、原文で罫線「━━━…」の後に人物ラベルが出て、その後に同じインデントで続く文字列は、その人物の台詞の続きなので、その人物の台詞のブロックに戻す。これは中身からの推し量りではなく構造で決まるので、上の例外とは別扱い。【AA内】になるのは罫線より前のAA領域の文字（右端文・縦書き・補足・効果音など）だけで、そこに「>>名前」があっても【名前（AA内）】のままにし、通常の台詞にはしない（295。ユーザーより。GPTの変換方針にもこの一文が入った）。試合の最初、両チームのサポート効果の表示の間に出てくる台詞は、相手チームの6体のうちの1体のカットインなので、その名前の話者はそのポケモン（241のコダール、245のムック。ユーザーより）。変換版の【作者・AA内】も、物語の途中にあるものは作者の言葉ではなく、全部その場のキャラの声（「※カズマさん」のような注釈もふくむ。作中で作者の言葉が出ることはほぼない。ユーザーより）。すぐ後のキャラの台詞に付随する形なので、話者のない【AA内】と同じく、基本はすぐ後の台詞の人物にする（「>>名前」があればその人物）。作者のまま残すのは、話の最後の「本日は以上にて」などの書き込み、イベントや安価の告知・募集、ダイスの結果の行、System表示の書き間違いを作者が自分で正した注記（398の「ああ、回復だよ回復>>「タスキ」復活」。ユーザーより）など、物語の外の書き込みだけ（275）。話の冒頭、物語が始まる前のメタ空間のAAの発言も、作者ではなくキャラが話している（010の「私にもあのくらいおっぱいほしい>>アクア様をみながら」はルサルカ。ユーザーより）。「>>名前」の相手が言葉を話さないポケモン（鳴き声だけ）なら、「その存在について」の意味として扱い、ほかのルールで話者を決める（015の「>>ライガー」は渚。ユーザーより）。説明の途中に挟まった、話題の人物の様子を描いたAAの台詞（回想・イメージ）は、その人物のもの（015のスペランカー。ユーザーより）。誰か決まらなければユーザーに聞く。「ようこそ、バーボンハウスへ。」のような有名な掲示板のコピペ（AA）は、誰かの台詞ではなくネタとして貼られたものなので、話者を付けずに【AA内】のまま元の位置に置く（371。名前が似ていても、その人物（安室＝バーボン）の台詞にしない。ユーザーより）。ただし、その場のキャラ自身の有名なネタ（394の脹相の「存在しない記憶」など）は、そのキャラのものにする（ユーザーより）。作者はタフ語録などのネット語録を使うので、「〜っすね」のような言い回しや、「必要な分は見せた、これ以上は見せぬということだ」のような古風なネットの言葉も全キャラが使う（377。ユーザーより）。口調だけで話者を疑わない（ユーザーより）。「あへ あへ あへ あへ」のAAは、すぐ後の台詞にかかわらず常にホシノ（389。ユーザーより）。マックイーンのワッフルのAAは、毎回「ワッフルといえば／コレですわ／種類いっぱいありますけども／チョコですわ／これだけあれば／勝ちですわ」の6行で、GPTはこのうち3行を落とすことがある（078。この先も50回ほど出る。ユーザーより）。欠けていたら6行に補い、原典の修正記録に書く。「もしアカンと判断したら／おしぼりを投げつけてくれても／かまわんで」「疾風迅雷やね」の吹き出しのAAは、直哉の定番ネタで、常に直哉（020。AIが誰の言葉か迷いやすい。ユーザーより）。これで埋めてから保存し、「原典の修正記録」に書く。報告は数だけにし、本当に迷うものだけユーザーに聞く（ユーザーより。確認が面倒なため）。差し替えの報告は2〜3行にとどめる。作者が出した安価の募集・ダイスの結果・それで決まったことは、読者のレス本文と違って原典に残す（151以降はGPTにそう頼んである。ユーザーより）。新版で抜けていたら旧版から補う。GPTが足した地の文（AAの場面説明）に読み違いがあれば、差し替えのときにその場で直してよい（自分で間違いだと思ったものも直す）。直したら「原典の修正記録」に書き、報告で一言触れる。すでに差し替えた過去の話も、さかのぼって探して直す（ユーザーより）。
- **原文の貼り付けからまとめる手順**（211で使った。212からはGPTの変換版に戻したので、今はGPTが使えないときなどの予備。ユーザーより）: ユーザーが原文を貼り付け（とスクショ）で渡し、Claudeが原典にまとめる。貼られたものは届いた順に `notes/raw/NNN_raw.txt` にそのまま残し、ユーザーが「ここまで」と言ったら `source/NNN_タイトル.txt` にまとめる。まとめ方は今までの原典の書式に合わせる（【話者】の行、System は「◎」、作者の安価の募集・ダイス・結果は残し、読者のレスは省く。AAの残骸（記号だけの行など）は捨て、AA内の台詞は【名前（AA内）】で、話者のルールは上のとおり。区切りの「━━━」は話者の切れ目として使い、残さない）。言い換えや要約はしない。迷う行はスクショと照らし、それでも分からないものだけ聞く。cmp の確認はできないので、まとめた時の判断は `notes/source-edits.md` に書く。
- 作り直した版は、差し替える前に書式が崩れていないか測る（台詞の話者名、【System】、図鑑の行を除いた本文で）。1行の平均が18字を下回る、8字以下の細切れの行が30%を超える、「――――」で終わる行が10を超える、のどれかに当てはまったら、差し替えずにすぐユーザーに報告する（ユーザーの指示。旧版の崩れは平均9〜10字、細切れ50〜60%だった）。
- バトル回は、System表示（「◎」の行、「こうかは〜」「〜は倒れた！」、ダメージ・残り体力の表示、Tごとの状態表示）が残っているかも数えて、前のバトル回（191・194など）と比べる。要約の地の文に置き換わっていたら、差し替えずにすぐユーザーに報告する（199・200で起きた）。ただし、作者がやることの分かりきったTを安価なしの安定行動で進めることが1試合に1〜2回あり、そのTは状態表示と指示安価がない（209のT9など。ユーザーより）。これは抜けとして扱わない。変換版で話者と台詞が同じ行（「【凛】ほーん、…」）になっているのは原文の書き方なので崩れではない。原典の書式に合わせて【話者】の行と台詞の行に分けるだけで、報告しない（ユーザーより）。図鑑の『専用』ポテンシャルの前後に入る「zzzz…」だけの行は、作者が『専用』を額縁のように囲んで特別感を出す飾り（AAの残骸ではない。377。ユーザーより）。記号だけの行なので消してよく、報告もしない。縦書きのAAの文字が1〜2文字ずつばらばらの行になるのも、縦読みのAAのせいでGPTの崩れではない。読める形に組み直して原典の修正記録に書くだけでよい（240。ユーザーより）。ほかにも、GPTの出力が前と比べて崩れている・変わってきていると気づいたら、黙って直すだけにせず、どんどんユーザーに伝える（ユーザーより。言われないと気づけないため）。
