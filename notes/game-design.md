# ゲーム化の設計メモ

原典の世界をゲーム（バトルを中心に遊べるもの）にするための決めごと。ルールそのものは各資料に書き、ここには決まったことの一覧と、まだ決めていないことを置く。

## 遊び方の範囲（補足: ユーザーより）
- プレイヤーは**自分のチームを組んで**遊べる（カズマ側を動かすだけではない）。
- **オリキャラ**（オリジナルのトレーナーやポケモン）も作れるようにする。
- 相手は、[world/opponent-ai.md](../world/opponent-ai.md) の敵AIのモデルで動かす。

## 決まったこと（ゲームで回すとき）
| 項目 | 決めたこと | 書いてある場所 |
| --- | --- | --- |
| ランク→種族値 | 「+」は幅の最大値、「-」は最小値、素は中央あたりからランダム、Sは200超えのどこか | [battle-rules.md](../world/battle-rules.md) ステータスのランク |
| 能力値の式 | 実機の式で、個体値・努力値・性格補正なし | 同上 |
| 体力（マスクデータ） | 耐久が高くなさそうならC、まあまあB、ちゃんとあるA、それ以上は凄そうなもの | 同上 |
| 体力の見せ方 | 数値を見せず、言葉（「大きなダメージ」など）と＠で見せる。表示はいつも最大体力に対する割合 | 同上、ダメージ表示の目安 |
| 倍率の重ね方 | ランクの上昇・強化・威力の倍率は全て掛け算 | 同上、能力の「上昇」と「強化」 |
| 確率 | 中確率50％、低確率1/8、稀に1/16。『気合い』は12.5％×（1−残り体力の割合） | 同上、確率の目安 |
| 同時に起動する効果の順 | 素早い方から。1体の中は特性→『役割』→ポテンシャル欄の上から順 | 同上 |

## オリキャラのトレーナーの作り方
- **資質は「C・C・B・A」の4つを、指示・育成・統率・能力に1つずつ割り当てる**（補足: ユーザーより。「C」ランクのデフォルトの形。→ [pro-trainer.md](../world/pro-trainer.md) の資質の総合的な高さ）。
- **割り当てはダイスで決める**（補足: ユーザーより）。手順の案: ①1D4でAの資質（1指示・2育成・3統率・4能力）、②残り3つから1D3でBの資質、③残り2つがC。Aになった資質で「〇〇型」が決まる。
- **「+」「-」は最初は付けない**（補足: ユーザーより。めんどいので）。ただし**あとで実装できる余地を残す**（資質のデータに「+」「-」を持てる欄を用意しておき、最初は空にする。「+」は1ランク上の効果の一部、「-」は何かが欠ける、という資料の考え方に合わせる）。
- **『固有』は最初から作れる**（補足: ユーザーより）。原典で分かっている決まり（→ [potentials.md](../world/potentials.md) のトレーナーの『固有』ポテンシャル）に合わせる:
  - 数は「能力」のランクで決まる: C は1個、B は1〜2個、A 以上は2〜3個。
  - 「能力」が高いほど、発動条件が広くて強い（A なら「味方が場に出たとき」のような広い条件で発動できる）。低いと、自分の資質に合った**条件付け**が要る（カズマの「能力：C」は、統率型らしく『役割』の発動をトリガーにした）。
  - 主な資質（Aの資質）が、『固有』の発動条件や中身に出やすい。
  - 実例の型: 技能拡張（パーティ全員がある技を出せる。ハイランダー、ロビンマスク、エール、天花）、場に出た時の強化（先輩、レヴィ）、『役割』の発動がトリガー（カズマ、ダージリン、観音寺）、『指令』や「タイム」や四式がトリガー（直哉、イングリッド、ブリジット）、フィールド形成（万丈目、レナ）など。

## まだ決めていないこと
- オリキャラのトレーナーの作り方の残り（『固有』をどこまで自由に作るか、強さの釣り合いの取り方。「+」「-」の付け方はあとで）
- オリキャラのポケモンの作り方（種族値のランクの合計の目安、ポテンシャルの数と構成、Lv）
- チームを組むときの制限（ランクごとのLv帯、要「統率」、『専用』や種属のレギュレーション）
